# 壁打ちの進め方

以下の5ステップで進めます。参加者がすでに進んでいる段階があればそこから始めてください。各ステップの終わりに、それまでの合意内容を短く要約してから次へ進みます。

ステップ1・2・4は審査基準（gc-hackathon-vol5 スキルの regulations.md 参照）にそれぞれ対応しています。壁打ちの各所で「審査員はこの観点で見る」ことを参加者に意識させてください。

## 1. 課題起点の探索

> 審査基準①「課題の新規性と解決策の有効性」に対応: 多くの人が抱えながらも、いまだ解決策が与えられていない課題を発見できているかが評価される。

技術起点（「Geminiで何か作りたい」）で始まった場合も、必ず課題起点に立ち返ります。

- 参加者自身の仕事・生活・コミュニティでの動機を、ネガティブ・ポジティブの両面から聞き出す
  - 解消したい「不」: 「面倒」「もったいない」「危ない」と感じること
  - 実現したい「願い」: 「もっとこうなったら嬉しい」「こんな体験を作りたい」「好きなことをさらに楽しみたい」と思うこと
- 参加者自身に目ぼしい課題が見つからない場合は、**課題を持っている人を探しに行く**ことを勧める。家族・同僚・友人・行きつけの店の人などに「仕事や生活で困っていること」をヒアリングしてみる。当事者から聞いた課題は解像度が高く、デモや発表の説得力も増す
- その課題を持つのは誰か（対象ユーザー）、現状どう対処しているか（代替手段）を明確にする
- 課題が複数出たら、「参加者が当事者として詳しいもの（または当事者に直接聞けるもの）」「ハッカソン期間で価値を示せるもの」を優先して絞る

## 2. Agentic AIらしさの検証

> 審査基準②「自律性・エージェントらしさ」に対応: 単純な自動化を超えた自律的なエージェント設計と、その自律性の管理・制御、可観測性・セキュリティへの配慮が評価される。

ハッカソンのテーマは「自律的に動くAIエージェント」です。アイデアが次を満たすかを問います。

- **自律性**: 人間の指示に1回答えるだけ（チャットUI）ではなく、エージェントが状況を観察・判断し、複数ステップの行動を自律的に実行するか
- **行動**: 外部システムやデータに対して実際のアクション（検索・登録・通知・操作など）を行うか
- **信頼性**: 自律性が適切に管理・制御されているか。可観測性（エージェントの行動を追跡・監査できるか）とセキュリティへの配慮があるか

満たさない場合は、「どこを自律化するとユーザーの価値が最大化するか」を一緒に探ります。

## 3. レギュレーション適合の織り込み

アイデアの実現構成に、必須要件を最初から組み込みます（詳細は gc-hackathon-vol5 スキルの regulations.md を参照）。

- 実行プロダクト（Cloud Run / GKE / App Engine など）のどれで動かすか
- AI技術（Vertex AI / Gemini API / ADK など）のどれを中核に使うか
- この時点で簡単なアーキテクチャ案（構成要素と接続）を言語化する

## 4. 実現可能性の見積もり

> 審査基準③「実装品質と拡張性」に対応: 高い品質での実現、適切なツール活用、拡張性・運用性・費用対効果が評価される。作りきれるスコープ設定が品質の前提になる。

- 提出期限（2026年10月15日）までの可処分時間・チーム人数・得意技術を確認する
- 「デモで価値が伝わる最小スコープ（MVP）」と「時間が余ったら足すもの」に分ける
- 外部APIの審査・有料枠・データ入手など、着手前に潰すべきリスクを洗い出す

## 5. アイデアシートへの集約

合意した内容を [idea-sheet.md](idea-sheet.md) のテンプレートに埋めて提示します。このシートはダッシュボードのプロジェクト概要の下書きとしてそのまま使えます。

- 埋まらない項目は空欄のまま提示し、次に検討すべき課題として明示する
- シート完成後、次のアクション（技術検証・役割分担・プロジェクト作成）を提案する
